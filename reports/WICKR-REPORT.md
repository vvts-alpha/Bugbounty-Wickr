# AWS Wickr 6.72.20 (Windows desktop) — 0-day hunt: running report

**Status: COMPLETE (2026-07-24).** Authorized bug-bounty RE for responsible disclosure. Profile B thick-client. **Verdict: NO confirmed WIN within scope — comprehensive run-to-prove negative + notable hardening findings.**
**Target:** AWS Wickr `WickrPro.exe` v6.72.20 (installed 2026-07-24, confirmed latest), native Qt6/QML.
**Accepted WINs:** victim code-exec · memory-corruption primitive · loopback IPC/HTTP→RCE · auth/E2EE break.
**Attacker ceiling:** ≤ one-click / victim-opens-content / same-machine-unauth-local / web→loopback.
**Excluded from any WIN:** MITM, non-default config, local-admin, AWS prod infra, 2nd unproven bug, known/patched CVE.

## FINAL VERDICT — no clean WIN; comprehensive negative + hardening findings
Exhaustive multi-agent audit (8 surfaces, ~10 agent-deployments, run-to-prove) found **no vulnerability meeting the WIN criteria** (victim code-exec / memory-corruption primitive / loopback-RCE / auth-E2EE break) reachable within the attacker ceiling on a stock install. Wickr 6.72.20 is mature and well-hardened: message/transport core = memory-safe Rust (mls-rs); calling RTC engine uniformly bounds-checked; OIDC-loopback, deep-link and WebChannel-bridge layers enforce their invariants; content/attachment/QR/image handling defensively coded.

**Strongest result — REPORTABLE hardening finding (verified primitive, escalation blocked by a single barrier):**
1-click `.docx` preview → docx-preview `renderSymbol` injects **unsanitized raw HTML** (`innerHTML = &#x${w:sym/@w:char}`) into a **same-origin, un-sandboxed** preview iframe that **can reach the full `WebChannelMessageBridge`**, and the parent already forwards `openLink` to a native sink. **Two of three RCE-chain links are open; the sole barrier is the CSP** (`script-src 'self' qrc://*`, no unsafe-inline/eval). Dedicated bypass hunt (script-gadgets, DOM-clobbering [works], `<base>`/`<meta>` [works], qrc script-reuse, non-script bridge reach) confirmed the CSP holds. **Any CSP regression → clean 1-click renderer→bridge→RCE.** Fixes: `sandbox` the preview iframe (drop `allow-same-origin`), hex-validate `w:sym/@w:char`, validate parent `message` origin.

**Other DiD observations (not wins):** bridged chat view ignores TLS errors + auto-grants cam/mic/geo + full bridge, gated only by dev-only `webViewAddress` (P1); bounded OOB read in FEC (P2); loopback Host-header unvalidated (N1); calling is DTLS-only, no SRTP/SFrame E2E layer (P2).

**Honest residuals NOT closed (need infra beyond this env; low prior given static results):** MLS E2EE auth-break via live malicious peer (2-account crafted-message injection — all checks present statically, no bypass indicator); calling dynamic fuzz with a live malicious peer; full real IdP SSO login not driven end-to-end.

**Excluded-by-scope:** WinSparkle auto-update (DSA-signed; needs MITM+sig-bypass), Sock5 tunnel (WOA off-by-default), DLL search-order hijack (needs local write), Chromium/Qt n-day CVEs.

## Confirmed WINs
**None** — no vuln met the WIN criteria within the ceiling on a stock install; see Final Verdict.

## Verified primitives / partials (short of a clean WIN)

### P1 — Chat-view "popcorn override" (`webViewAddress`) → full-bridge remote-content takeover — GATED
- The single WebChannel-bridged WebEngineView loads `wickrSettings.webViewAddress` (default `qrc:/index.html`, runtime-confirmed). That view has the full 58-method `WebChannelMessageBridge` **and ignores TLS errors and auto-grants camera/mic/geo**.
- `webViewAddress` is a mutable QSetting ("popcorn override"). If ANY attacker-reachable path writes it (or otherwise repoints that view), the view loads attacker remote content **with the full native bridge** = RCE-grade takeover.
- **Gate (why not yet a WIN):** A2 found no attacker-reachable set-path from deeplink/webchannel; local config write is EXCLUDED. OPEN (→A7): server-pushed "popcorn"/feature-flag config write-path, or logged-out `wickrpro://register?…serviceHost=attacker` repointing a fresh client's bridged onboarding view (A2 flagged, not executed).
- **RESOLVED → NEGATIVE (A7, see `A7-view-repoint.md`).** The bridged view's URL `webViewAddress` writer (`setValue` fn [0x1409ec860..)) has exactly ONE caller = `wickrSettings::qt_static_metacall` [0x140a99580..), driven **only** by the React WebChannel setter wired to the local field `"Custom Web View Address (For development only)"` (dev-only, non-default, local ⇒ EXCLUDED). No native `invokeMethod/setProperty("webViewAddress")` (meta-str 0x14327c1f9 has 0 refs). Every server-pushed channel enumerated and carries NO view-URL: `SwitchboardMessage.Logon.featureFlags` = {`messageUpload` bool, `typingIndicator`}; onboarding `loadBootStrapJson` [0x1409c7b70..) keys = {usernameMode,username,inviteCode,requireEmailVerification,userManagedCredentials,serviceHost,serviceSSLKeys,serviceRegKeys,companyId,compliance,pubKey,regToken} — no `webViewAddress`. Onboarding UI is native QML (`/qml/AWSWickrProOnBoarding/*.qml`); exactly ONE `webChannel:` in the binary (chat view). So logged-out `register`/`WOA` with attacker `serviceHost`+`cert` makes attacker the REST/provisioning server (malicious-server, MITM-class, bridgeless) but CANNOT repoint the bridged view. Runtime (frida, live PID): register/WOA/sso-verify/`webViewAddress=`-param deeplinks → `setWebViewAddress`/`loadBootStrapJson`/register-handler never fired; live view stayed `qrc:/index.html`. (Caveat: fully logged-out run not executed — session-independent blocker makes it non-decisive.)

### P2 — Calling / RTP path (NPL) — reachability CONFIRMED, top sinks under audit (UNCONFIRMED)
- **Reachability (strong):** UDP(`WSARecvFrom`)→**DTLS decrypt**(SecureConnection, ssl.dll `DTLSv1_2`, ECDHE-ECDSA-AES256-GCM)→DataChannel→Wickr parsers (XorFec/Reorder/Reliability/PacketBundle)→codecs. **SINGLE crypto layer = DTLS only**, P2P role-negotiated; `Sock5.dll` UDP relay is a pure forwarder (doesn't terminate DTLS). ⇒ the **CALL PEER authors the post-DTLS bytes** feeding Wickr's parsers — **attacker-controlled end-to-end, NO 2nd bug**. Ceiling ≥1-click (victim answers); 0-click pre-answer not yet proven.
- **Audited sinks all bounded (no OOB write):** FEC XOR recon @0x1800e3720 (output alloc == recovered-len; XOR/memmove clamped `min(src,len)` via `cmovb`@0x1800e38d1); ReorderingBuffer::AddPacket @0x1800bb700 (min-size guards 0x21/0x25/0x2a + /GS cookie, windowed list); channel-config @0x180150100 (formats [1..8], rates clamped, jump-table range-checked).
- **Residual (non-win):** bounded OOB **READ** ≤2047B in FEC path-B @0x1800e3720 (r14d=11-bit attacker len drives memmove seed read w/o size check); local-consumed by codec, non-exfil, non-crashing → outside win list.
- **A6 continuation (video+signaling) — BOUNDED, no OOB:** video decode-input→libvpx (CVE-excluded); output plane-copy alloc==`W×H`, libvpx-capped dims, no int-overflow; signaling dispatch + DTLS-handshake handler bounded (protocol-const checks; DTLS=OpenSSL). **CEILING RESOLVED = 1-click POST-ANSWER** (INVITE=MLS/Rust→ring→user answers→deferred `handleStartCall`→NPL/DTLS; no auto-answer/pre-ring connect ⇒ NOT 0-click).
- **A6 FINAL (video+signaling) — CLOSED/BOUNDED:** enumerated ALL memcpy/memmove in video region 0x180140000–0x180170000; copy-dense sites are std::string/JSON (SSO-guarded), not frame data; fragments use a pooled ref-counted `NPLPacket` chain (`NPLPacketLink/Next`) — **NO attacker-offset contiguous reassembly memcpy exists** (bug-class architecturally absent). Hub pub/sub: channel index = bounded map (`cmp edi,0xbff`), stream-id = safe std::string. Video+signaling half fully bounded, no OOB.
- **A9 (audio/reliability/bundle/demux) — CLOSED/BOUNDED:** audio depacketizer (`PacketBundleDecoder` @0x1801650b0: len≤1024, K≤31 subframes, per-subframe `edi-=(len+1);jle` cursor guard); DataChannel demux @0x1800da050 (32-entry cap); ReorderBuffer<WrapAroundIndex> @0x1800bc3e0 (`seq mod cap` before write); reliability demux @0x1800be290 (FNV-1a+mask map); TLV parse @0x1800bef10 (per-block bounds); clone alloc==content; teardown refcount+**null-after-free** (defeats UAF). Live byte-matched vs running module.
- **P2 VERDICT — NEGATIVE (static, thorough):** entire Musigy RTC engine (both halves) uniformly bounds-checked; reachable (peer authors post-DTLS bytes, no 2nd bug) at **1-click (post-answer)**; no memory-corruption primitive found. **Residual (not done, low-prior):** dynamic fuzz with a live malicious peer (adversarial reorder / dup-ack / malformed frames into an active call); + 2-account E2EE/auth-logic testing (see N2) — both need real call/2-account infra; recommended future work.

## Well-verified NEGATIVES (surfaces closed)

### N1 — Loopback HTTP server (127.0.0.1) — OIDC SSO callback receiver — NEGATIVE
- **What it is:** Qt 6.9.2 stock `QOAuthHttpServerReplyHandler` (Qt6NetworkAuth.dll), used by Wickr `WickrOIDCWorkFlow` as the RFC 8252 authorization-code loopback receiver. Binds `127.0.0.1`, **OS-random port per launch** (WickrPro.exe @0x140ad2e71). NOT Sock5's libevent httpd (red herring).
- **Callback:** `GET http://127.0.0.1:<port>/?code=…&state=…`; non-`/` paths closed. Flow: `callbackReceived`(RVA 0x3900) → `authorizationCallbackReceived`(RVA 0xb7c0) → state-validation @0x18001b8d0 → `requestAccessToken` (PKCE) → stores sso{Access,Refresh,Id}Token.
- **Why no win:** `state` = per-login CSPRNG (`QRandomGenerator64::system`), exact-match-or-reject (@0x18001b8fc) + PKCE → code injection/CSRF rejected pre-exchange (observed via frida: callback fired, NO token exchange). Theft impossible (inbound-only, no CORS, socket not stealable). No RCE/SSRF/file sink (fixed stub on `/`). DiD: random port, on-demand lifecycle, browser PNA.
- **Residual (non-win):** `Host` header unvalidated (DNS-rebind-relevant but nothing to steal/forge). Limitation: full real IdP login not driven (no SSO test net); static disasm unambiguous + idle-injection negative observed.

### N2 — MLS / NPL wire parsers (0-click memcorruption + E2EE) — NEGATIVE
- **WickrMlsSdkCpp.dll = Rust:** statically links `mls-rs 0.54.0` (audited RFC 9420), mls-rs-codec, HPKE, uniffi glue, rusqlite/SQLCipher. Message decode/decrypt/verify path = **memory-safe Rust**; only C++ is bounds-checked FFI glue over Rust buffers (`FfiConverterBytes::read`@0x180bf3600 checks len≤remaining & <0x7fff…). Worst case = caught panic = DoS (not a win).
- **NPL.dll = A/V calling engine** (Musigy), NOT a message parser. `NPLPacketFromData`@0x1803cbc90 rejects negative length. Codecs 3rd-party (CVE-excluded).
- **E2EE:** all mandatory MLS checks present in-binary (signature/confirmation-tag/membership-tag/tree-hash/epoch/sender-type). No static bypass indicator. (Definitive auth-break test would need dynamic malicious-peer injection — not done.)

### N3 — Deep-link `wickrpro://` + WebChannel bridge (1-click / renderer→native) — NEGATIVE
- **WebChannel:** 58-method `WebChannelMessageBridge` (+uiBridge/onboarding/settings/serverModel/environmentMgr/fileManager) exposed to exactly ONE WebEngineView, which loads `webViewAddress` = default `qrc:/index.html` (local React app), hardened by CSP `script-src 'self' qrc://*` + DOMPurify 3.2.5; message links = React onClick (no href/nav); file previews in postMessage-isolated child iframe. Remote-content views (SSO IdP, bot `webAppLoadUrl`) have NO webChannel. → attacker content never loads with bridge attached.
- **Deep-link:** single-instance via `SingleApplication` (local named pipe, not web-reachable). Router @0x140ad2b50 gates sso-verify (needs active flow + `redirect_uuid==grantRedirectUuid`), forgotpassword (same-user + server `transId`), register/WOA (ignored when logged-in). Frida: forged probes classified (ret 2/3/0) but hit ZERO open/nav sinks. Link-open validator @0x1409c7950 = scheme allowlist (only mailto/http/https reach `QDesktopServices::openUrl`).
- **Residuals (not wins):** see P1 (webViewAddress); bot webviews ignore cert errors (MITM-excluded).

### N4 — Post-decrypt content & attachment handling (traversal / write / SSRF) — NEGATIVE (1 residual open)
- **Save (1-click)** @0x14006d350: file-id QUuid-validated (@0x1409000e0); display name via `QFileInfo::fileName()`+`..` check; write via `QFileDialog::getSaveFileName` (USER picks path). No attacker write.
- **Open (1-click)** @0x140070410: decrypts to sandboxed `temp/preview/Preview_<UUID><ext>`; ext can't contain `..`. Backstops: Mark-of-the-Web (@0x140b617d0)→SmartScreen, openFileAllowList, auto-download stores but NEVER auto-opens. Not 0-click RCE.
- **Link open (1-click)** @0x14006f610→validator @0x1409c7950: instruction-verified strict allowlist `http/https/mailto` (`sete al` polarity confirmed). No `file://`/scheme-abuse/UNC.
- **SSRF:** none — link previews sender-generated + DB-stored (no receiver `QNetworkAccessManager::get`); download host = baked-in allowlist (`gw-pro-prod.wickr.com`, `api.messaging.wickr.*.amazonaws.com`, GovCloud/IC) + account config. **Zip-slip:** none (no `QZipReader`; received archives = opaque encrypted blobs).
- Dynamic frida on live PID: no anomalous writes/egress.
- **RESIDUAL (open, UNCONFIRMED, potentially a 0-click WIN):** exact 0-click auto-download write-site (S3-client subsystem) not disassembled to instruction level — does attacker `realfilename` reach `CreateFileW`/`QFile::open` WITHOUT QUuid-canonicalization? If yes → **0-click arbitrary-file-write**. Indirect evidence favors QUuid-canonical (negative). → **A5 resumed to close.**
- **Handoff:** embedded **SheetJS/jszip/SocialCalc** parse attacker-sent spreadsheet/archive content **in-memory in a postMessage-isolated child iframe** in the WebEngine view — renderer-side attacker-content parse (not a native FS write); escalation would require escaping the iframe isolation to reach the bridge.

### N5 — Sock5 / QR (QZXing) / media decoders — NEGATIVE (1 residual under close-out)
- **Sock5.dll = Dispersive VDN SOCKS5 tunnel** (censorship-evasion; `SOFTWARE\Dispersive\Vdn`, libevent, `DispersiveTunnelStart/Stop`), gated behind **Wickr Open Access (WOA) = OFF by default** (verified live: no SOCKS listener, WOAVendor empty). Parser fed by trusted local client; only remote bytes = tunnel responses (MITM/malicious-server = EXCLUDED). Non-default + no in-ceiling input → NEGATIVE.
- **Chat image decode = Chromium** (QtWebEngine), NOT Qt imageformats plugins → stock Chromium (Qt/Chromium CVEs excluded). Qt plugins reached only via native QML (avatars/onboarding), not 0-click.
- **QZXing3.dll** (Wickr-shipped ZXing port): reachability CONSTRAINED (NOT 0-click) — QR decode only in onboarding/recovery/device-sync QML (camera scan or drag-drop `decodeImageFromFile`; QR-only). ~76k live `decodeImage` invocations; 1 non-reproducible AV (judged coincidental cross-thread) → UNCONFIRMED.
- **RESIDUAL (under close-out, A4 resumed):** DecodedBitStreamParser count/length bugs (classic ZXing sink) unreached by module-level mutation (RS repairs tampered codewords). → crafting RS-VALID malicious payloads to reach it; ≥1-click (constrained: device-sync/recovery scan/drop) if hit.

### N6 — Renderer file-preview (SheetJS/JSZip/docx/pptx in child iframe → escape → native bridge) — NEGATIVE (A8, `A8-renderer-preview.md`)
- Resolves the N4 handoff. The attacker-sent spreadsheet/archive/doc preview **is** attacker-file-reachable & ≤1-click (`openFile`→`FilePreviewModal` when `enableFileDownload` off, or File-Management non-image files). Attacker controls file **bytes + extension** (extension = renderer selector, via `location.hash`; `fileUrl`=`wickrweb://` served by native).
- **Iframe isolation is ILLUSORY but moot:** the preview `<iframe>` is **same-origin qrc** (proven: `withLinkHandler` uses `window.parent.origin` as postMessage targetOrigin — throws if cross-origin) with **NO `sandbox`/`srcdoc`** anywhere in the binary. A `'self'` script trivially reaches `parent`'s bridge / `qt.webChannelTransport`. So "postMessage-isolated" is inaccurate — it's same-origin + a postMessage convention.
- **The real, load-bearing blocker = CSP `script-src 'self' qrc://*` (no `unsafe-inline`/`unsafe-eval`).** Output-escaping is a first layer but is **NOT airtight**: TextPreview/RTF→escaped `<p>{line}</p>`; XmlPreview→`DOMParser`(inert)→escaped tree; spreadsheet(SheetJS, no `sheet_to_html`)→escaped React table; PPTX→**DOMPurify**→`dangerouslySetInnerHTML`; **BUT docx-preview `renderSymbol` does `t.innerHTML=\`&#x${e.char};\`` with attacker-controlled `e.char` → genuine HTML injection into the preview DOM.** (Note: main bundle has 17 `dangerouslySetInnerHTML` — 16 react-dom/preact internals + 1 app icon renderer fed app SVGs; an earlier "one sink binary-wide" figure was an exe-zlib-compression artifact, corrected via decompressed carves.) So attacker HTML *can* reach the DOM — the CSP, not escaping, is what stops escalation to JS.
- **PROVEN by execution** (`scratchpad/harness/`, Chromium=Blink CSP engine): same-origin un-sandboxed iframe + exact CSP + parent bridge stub. 7 attacker vectors injected via `innerHTML` (inline `<script>`, `<img onerror>`, `<svg><script>`, `javascript:` URI ×2, `<body onload>`, mXSS) + `eval`/`Function`/dynamic-`<script>`. Observed: `pwned:[]` (0 executed; script/img nodes present but INERT), `eval`/`Function` CSP-blocked, `parent __RCE__=undefined`. Same-origin reach confirmed open (`iframe_can_read_parent_bridge:true`) — but never exercised because no attacker code runs. `__proto__` cluster = Rollup `{__proto__:null}` module namespaces (not a pollution sink).
- **Only attacker→parent channel:** clicked-hyperlink `{type:'openLink',url}` → parent `ui/openLink` thunk (+"leaving Wickr" confirm) → native `uiBridge.openLink` = **data-only, 2-interaction**, bounded by N4's strict `http/https/mailto` allowlist (PPTX hrefs also DOMPurify-filtered). Not code-exec.
- **CSP-bypass hunt (all 5 classes) — PROVEN inert (harness v2):** script-gadgets (only sinks = JSZip setImmediate `new Function` [CSP-blocked + fn-only] + empty timing-`<script>`; docx `renderAltChunk` srcdoc gated `renderAltChunks=false` & srcdoc inherits CSP); **DOM clobbering WORKS** (`window.__loaderCfg`←injected `<a>`) & **`<base href>` WORKS** but **no weaponizable sink** — clobber→real `<script>` is CSP-blocked at load, `eval`/`Function` blocked; **`<meta>` CSP cannot be relaxed** (`meta_csp_relaxed:false`, policies AND-combine); qrc/'self' script-reuse runs app code not attacker; only child→parent message is `openLink` (bounded). Observed `pwned:[]`, `__RCE__=undefined`.
- **VERDICT: renderer surface DEFINITIVELY CLOSED.** Notable chained latent weakness (single-barrier): 1-click docx → unsanitized HTML injection → same-origin un-sandboxed iframe reaching the full bridge → parent already forwards `openLink` to native; **the sole barrier is CSP `script-src 'self'`**. Hardening recs: `sandbox` the preview iframe (drop `allow-same-origin`), hex-validate `w:sym/@w:char`, validate parent `message` origin. Any CSP regression → clean 1-click RCE.

## Mitigation posture (corrected)
All Wickr-authored binaries: DEP on, ASLR **with HighEntropyVA (full entropy)**, **CFG OFF**, /GS unconfirmed. Stock Qt DLLs: CFG on. → real weakness is CFG-off on Wickr code (unguarded indirect-call/vtable hijack); mem-corruption→RCE still needs an info-leak (ASLR is strong).
